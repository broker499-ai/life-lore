# Stage 17.3 — портреты и анимация перемещения лидеров

Это UI/presentation-этап поверх Stage 17. Игровая симуляция, RNG и save format не меняются.

## Портреты

- Убрана временная оранжевая debug-подложка Stage 17.2.
- Пять прозрачных портретов встроены в экран выбора лидера.
- На стратегической карте портрет выбранного лидера остаётся маркером основной армии на текущем узле.
- Финальный маркер оформлен как тёмный журнальный медальон с золотистой рамкой.

## Анимация перемещения

Для каждого лидера подключены три кадра ходьбы из присланных GIF:

- `frame-1` — шаг;
- `frame-2` — средняя/нейтральная фаза;
- `frame-3` — противоположный шаг.

Исходный красный фон и GIF-артефакты очищены программно; кадры хранятся как PNG с alpha transparency. У Илиеша удалён отдельный паук из исходной анимации, чтобы в карту попадал только персонаж.

После успешной команды перемещения:

1. `moveArmy()` сразу вычисляет валидный результат в core;
2. React хранит этот успешный результат как временный pending movement;
3. `SvgWorldMap` в течение примерно 1,05 секунды перемещает sprite между точными координатами двух узлов и переключает кадры ходьбы;
4. при движении влево sprite зеркалится;
5. только после завершения presentation-анимации UI коммитит уже рассчитанный `GameState` и запускает одноразовое POI-событие, если оно есть.

Таким образом renderer не определяет результат и не меняет правила движения.

На время ходьбы блокируются завершение хода, смена раздела и выход из кампании, чтобы пользователь не мог разойтись с pending state до завершения визуального перехода.

## Save / architecture

- save остаётся **v9**;
- pending movement не сериализуется;
- RNG не используется;
- `src/core` не изменён;
- ссылки на portrait/walk assets находятся в data-driven `LeaderDefinition`.
