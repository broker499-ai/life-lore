# Stage 08 — Battle Viewer Foundation

## Задача

Начать отдельную ветку развития боевой презентации. Не менять математический результат боя и не добавлять новую боевую систему.

## Сделано

- Добавлен `core/battles/presentation/BattlePresentation.ts`.
- Timeline группируется по времени и превращается в последовательность immutable presentation frames.
- Каждый кадр содержит:
  - фазу;
  - раунд;
  - условное время;
  - численность сторон;
  - мораль;
  - накопленные потери;
  - потери текущего кадра;
  - combat rolls;
  - состояние слома строя;
  - короткий presentation-текст.
- Добавлен отдельный `BattleViewer`.
- После штурма с реальным боем Campaign Screen автоматически открывает Battle Viewer.
- На поле показываются две формации точек.
- Позиция формаций меняется по фазе: позиции -> сближение -> контакт -> проверка морали -> перелом -> итог.
- Потери уменьшают число отображаемых точек.
- Есть scoreboard, morale bars, условный таймер, тактики и итоговые потери.
- Есть ручные Previous/Next и range scrubber.
- На финальном кадре можно вернуться на карту.
- После возврата финальный BattleResult остаётся доступен в панели города.

## Что намеренно НЕ сделано

- автоматическое воспроизведение;
- real-time simulation;
- пересчёт боя на стороне UI;
- Phaser;
- sprites/pixel-art;
- звуки;
- управление отрядами во время боя.

## Проверка

Headless smoke test для golden battle seed 42:

- BattleTimeline: 30 событий;
- BattlePresentation: 18 кадров;
- первый кадр: `opening`;
- последний кадр: `finish`;
- итог A: 24 -> 20, morale 80 -> 65, losses 4;
- итог B: 20 -> 14, morale 72 -> 44, losses 6;
- победитель: A.

Таким образом presentation layer не потерял и не изменил ни одного итогового показателя симулятора.

TypeScript app-layer проверен локально с временными декларациями React/Vitest, поскольку npm dependencies отсутствуют в рабочем контейнере. Временные declarations не включаются в проект.
