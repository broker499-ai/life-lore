# Stage 05 — единый BattleSimulator

## Цель

Создать полностью headless боевую математику до интеграции боёв в стратегическую карту и до Phaser. Один и тот же симулятор должен обслуживать малые и большие столкновения.

## Реализовано

- `simulateBattle(...)` — чистая deterministic-функция.
- Два масштаба через data-rules, а не через отдельные движки:
  - `skirmish` — 4 раунда, более плотный короткий timeline;
  - `battle` — до 6 раундов, более растянутый timeline.
- Вход боя:
  - roster обеих сторон;
  - мораль 0–100;
  - выбранная тактика;
  - battle RNG state;
  - unit definitions;
  - battle rules.
- Тактики прототипа:
  - натиск (`assault`);
  - стандартная (`balanced`);
  - осторожная (`cautious`);
  - обход (`flank`).
- Тактика меняет универсальные коэффициенты атаки/защиты, моральных потерь и нанесённых потерь; обход отдельно усиливает ranged-role без проверок конкретных `unitTypeId`.
- Потери распределяются по roster с учётом защитной устойчивости типа войск.
- Мораль пересчитывается каждый раунд.
- Слом строя прекращает бой и имеет приоритет над финальным сравнением «сырой» силы.
- Лестница исходов:
  - `victory`;
  - `pyrrhic_victory`;
  - `retreat`;
  - `rout`.
- `BattleResult` содержит оставшийся roster, потери по типам, мораль до/после, победителя, число раундов и новый `RngState`.
- `BattleTimelineEvent[]` уже пригоден для последующей React/Phaser-визуализации:
  - battle start;
  - round start;
  - d20-подобные combat rolls;
  - casualties;
  - morale changes;
  - line break;
  - battle end.
- Добавлены два локальных типа войск Орсии для headless-прототипов: стражи и пращники.

## RNG

BattleSimulator не читает и не меняет `GameState` сам. Он получает конкретный `RngState` и возвращает продвинутый state. На следующем этапе game command будет передавать `GameState.rng.battles` и записывать возвращённый cursor обратно.

Один завершённый раунд использует ровно два RNG-вызова — по одному d20 roll каждой стороне. Это делает golden tests предсказуемыми.

## Golden scenario

Seed 42, skirmish:

- экспедиция: 20 пехоты + 4 следопыта, мораль 80, balanced;
- Орсия: 14 стражей + 6 пращников, мораль 72, cautious.

Результат:

- победа экспедиции;
- 4 раунда;
- экспедиция теряет 4 пехотинцев, мораль 80 → 65;
- Орсия теряет 4 стражей + 2 пращников, мораль 72 → 44;
- Орсия отступает;
- battle RNG cursor: 0 → 8;
- timeline: 30 событий.

Этот сценарий закреплён golden-тестом и будет явно показывать изменение боевой математики при будущей балансировке.

## Проверено

- deterministic replay с одного и того же RNG state;
- input RNG state не мутируется;
- unit accounting сохраняется: remaining + losses = initial;
- morale всегда остаётся в 0–100;
- один simulator работает для обоих scale;
- timeline заканчивается `battle_end`;
- отдельно достигаются `rout` и `pyrrhic_victory`;
- headless execution golden scenario совпал с тестовым ожиданием.

## Намеренно не сделано

- применение BattleResult к GameState;
- атака города;
- гарнизоны городов;
- отступление армии по карте;
- смена владельца города;
- UI выбора тактики перед настоящим боем;
- Phaser-анимация.

Это следующий слой: стратегическая команда атаки должна оркестрировать уже готовый симулятор, но не переносить боевые формулы в command/UI.
