# Stage 19 — autosave, Continue и переход к штурму

Stage 19 делает законченную кампанию Stage 18 устойчивой к закрытию браузера/PWA и исправляет три UX-проблемы стратегической карты.

## Autosave и Continue

Добавлен browser-local persistence layer `services/saves/CampaignStorage.ts`.

Хранятся два слота:

- основной autosave;
- резерв — предыдущее отличающееся состояние `GameState`.

Autosave выполняется после изменений кампании. В результате автоматически фиксируются, в частности:

- завершение хода;
- обычное перемещение после завершения визуальной анимации;
- результат штурма перед показом Battle Viewer;
- найм и отдых;
- разрешение POI-события;
- получение Корня и terminal state кампании.

Изменение только UI — выбор узла, вкладки или камеры — обновляет основной save, но не перетирает полезный резерв предыдущего игрового состояния.

## Continue

Кнопка «Продолжить» в главном меню теперь работает.

При загрузке восстанавливаются:

- весь `GameState` через существующий `deserializeGame()` и его миграции;
- вкладка `Карта / Армия / Города`;
- выбранный узел;
- zoom и позиция камеры strategic map.

Battle presentation и незавершённая walking-анимация намеренно не сохраняются как отдельное состояние: результат боя принадлежит `GameState`, а presentation при reload возвращается к стратегической карте.

Если основной autosave повреждён, loader автоматически пробует резерв. Главное меню явно сообщает, что используется резервная копия.

## Ручное сохранение

В campaign toolbar добавлена кнопка `Сохранить`.

Она пишет тот же сериализуемый `GameState` немедленно, без отдельной несовместимой структуры сейва. После последующего реального изменения кампании autosave снова становится актуальным источником продолжения.

## Save version

Формат `GameState` не менялся, поэтому save version остаётся **v10**. Stage 19 добавляет внешний local-storage envelope с timestamp, причиной сохранения и безопасным UI snapshot; он не заменяет `serializeGame()`/`deserializeGame()`.

## Анимация штурма

`attackCity()` по-прежнему полностью рассчитывает исход в core до presentation. React не определяет результат.

После успешной валидации команды:

1. рассчитывается `AttackCitySuccess`;
2. результат временно держится как pending presentation;
3. спрайт лидера проходит от текущего узла к атакуемому городу;
4. после завершения walking-анимации рассчитанный state применяется;
5. при наличии боя открывается существующий Battle Viewer;
6. при пустом гарнизоне город просто занимается после прибытия.

При проигранном штурме визуальный подход к городу показывается до боя, а после Battle Viewer армия отображается на точке отступления, уже определённой core.

## Исправление карты

Stage 18 оставил `min-height` у `.world-map`, который мог быть выше реально выделенной grid-строки. Родительский `.map-frame` имел `overflow: hidden`, поэтому нижняя часть SVG визуально обрезалась и выглядела скрытой под карточкой локации.

В Stage 19 SVG подчиняется реальной высоте map row (`height: 100%; min-height: 0`). ViewBox целиком масштабируется в доступную область и карта больше не обрезается панелью описания.

## Командующие Орсии

Закреплены имена:

- Гоблины — **Тонкий Нечеловек**;
- Орки — **Моркогоркид**;
- Тираниды — **Дитя супа в столовой ГУМа**;
- Нацболы — **Лимоненко**;
- ФГУшники — **Темный Декан**.

Портреты Нацболов и ФГУшников поменяны местами согласно актуальному дизайну. Battle portraits остаются presentation-only и data-driven через определения орсийских субфракций.

## Архитектурные ограничения

- `src/core` для Stage 19 не переписывается.
- BattleSimulator остаётся источником результата боя.
- Autosave хранит сериализованный `GameState`, а не копию UI-state как новый игровой источник истины.
- localStorage errors не должны ломать кампанию: сохранение возвращает controlled failure.
- corrupted primary autosave не блокирует valid backup.
