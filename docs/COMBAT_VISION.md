# Боевой интерфейс — актуальное видение после Stage 11

## Цель

Бой должен ощущаться как короткий тактический матч в духе Football Manager: игрок принимает несколько решений перед столкновением, математический симулятор полностью определяет результат, а визуализатор непрерывно показывает давление, строй, потери, мораль и перелом боя.

Главное правило: **визуализация никогда не определяет исход боя**.

```text
тактика игрока
  -> simulateBattle(...)
  -> BattleResult + BattleTimeline
  -> campaign command применяет результат к GameState
  -> BattlePresentation восстанавливает состояние боя по событиям
  -> BattlePlayback задаёт непрерывное визуальное время
  -> BattleFormation рассчитывает геометрию строя
  -> React/SVG рисует бой
```

## Текущий визуальный язык

Пока вместо спрайтов используются точки-отряды. Это намеренный промежуточный стиль, позволяющий сначала довести читаемость боевой системы.

- сторона A слева, сторона B справа;
- поле разделено на левый фланг, центр и правый фланг;
- линейные войска образуют переднюю линию;
- стрелки располагаются глубже;
- число и прозрачность точек следуют реальному roster;
- потери конкретного типа войск редят именно соответствующую линию;
- движение строя показывает давление и отступление;
- три отдельных индикатора показывают положение фронта по секторам;
- залпы и короткие стрелки атаки являются SVG-представлением уже рассчитанного боя;
- сверху видны численность, мораль, тактика и время;
- под полем идёт комментарий текущего события.

## Выполненные этапы

### Stage 08 — Battle Viewer foundation

- отдельный экран боя;
- `BattleTimeline -> BattlePresentationFrame[]`;
- SVG-поле и точки двух сторон;
- численность, мораль, потери и тактика;
- ручная прокрутка событий;
- viewer открывается после настоящего штурма.

### Stage 09 — автоматическое проигрывание

- autoplay;
- play/pause;
- ×1 / ×2 / ×4;
- Skip;
- затухание потерь;
- визуальный pressure shift;
- reduced-motion режим.

### Stage 10 — непрерывный battle clock

- `requestAnimationFrame` вместо дискретных переключений;
- presentation frames стали keyframes;
- плавная интерполяция положения, морали, потерь и времени;
- Pause/Resume без скачков;
- scrubber перематывает в любую промежуточную точку.

### Stage 11 — тактическая геометрия

- три сектора: левый фланг / центр / правый фланг;
- front/rear lines;
- ranged располагаются за line;
- presentation отслеживает точный roster по типам;
- `assault`, `balanced`, `cautious`, `flank` имеют разные траектории строя;
- отдельное давление по каждому сектору;
- SVG-залпы стрелков;
- визуальные атаки/контратаки передней линии.

## Следующее развитие

Ближайшая задача — повысить содержательность самого timeline, не создавая второй симулятор:

1. помечать ключевые моменты: pressure swing, volley, flank attempt, counterattack;
2. отображать короткий журнал 3–5 важных эпизодов;
3. сделать инициативу более очевидной;
4. затем подключить местность и её боевые модификаторы;
5. только после этого решить, нужны ли pixel-art спрайты вместо точек.

## Phaser

Для нынешнего масштаба React + SVG остаётся достаточным. Phaser понадобится только если появятся сотни объектов, сложные sprite sheets, частицы, камера или существенно более тяжёлая сцена.

`BattlePresentation` и `BattleFormation` уже устроены так, чтобы в будущем стать DTO/входом для Phaser без переноса туда игровой логики.

## Ассеты

Для текущего Stage 11 внешние ассеты не нужны вообще.

Если позже точки заменяются на pixel-art, минимально понадобятся:

- пехота экспедиции;
- стрелки экспедиции;
- линейные войска Орсии;
- стрелки Орсии;
- простые эффекты удара/снаряда/попадания/отступления.

До принятия решения о pixel-art генерировать эти изображения преждевременно.
